# 숏폼 전용 세션 길라잡이 (10-15)

> 사장님 10-15 원문: «내 개인적인 생각에 쇼츠도 저쪽 컴퓨터에 맡기는게 좋아보이는데 저쪽 컴퓨터에서 쇼츠만하는 새로운 세션을해서 규칙충돌하지않게 만들고싶거든? 깃허브통해서 롱폼자동화한테 시켜서 공유 깃허브에서 참고경로만차이가 있게끔 설계해서 숏폼전용 폴더 및 세션 만들라고 지시해줘»

## 0. 이 세션이 누구인가

| | 기획 세션 | 롱폼 제작 세션 | **숏폼 세션(이 파일)** |
|---|---|---|---|
| 컴퓨터 · 폴더 | 기획 PC · 바탕화면 `한비즈-롱폼자동화` | 제작 PC · 롱폼 저장소 | 제작 PC · **`D:\숏폼전용`**(같은 GitHub 저장소를 따로 받은 것) |
| 역할 판별 | `핸드오프/역할.json` 컴퓨터 이름 | 그 밖 | **`핸드오프/역할.local.json` 의 `"역할": "숏폼"`**(git 제외 — 이 폴더에만 있음) |
| 시작 말 | «기획해» · «결과 확인해» | «확인하고 작업해» | **«숏폼 확인하고 작업해»** |
| 읽는 길라잡이 | `CLAUDE.md` + `.claude/skills/longform/` | 같음 | `CLAUDE.md` 공통 규칙 + **이 파일**(롱폼 규격·모드 A/B·`longform/SKILL.md` 는 읽지 않아도 됨) |
| 쓰는 파일 | 길라잡이 · `피드백/` · `기록/` · 건 폴더 `00_*` `20_*` | `tools/` · `소재/` · 건 폴더 `10_분석/` `30_*` | **건 폴더 `40_*` · `tools_shorts/` · `핸드오프/숏폼로그.md`** 뿐 |

**저장소는 하나, 폴더(작업 트리)는 둘.** 같은 폴더에서 롱폼·숏폼 세션이 같이 돌면 `git add -A` 가 서로의 파일을 쓸어 담는다 → 숏폼은 반드시 `D:\숏폼전용` 에서만 연다.

## 1. «숏폼 확인하고 작업해» 를 들으면

1. `python tools/handoff.py 상태` (받기 포함) → «숏폼 대기» 건을 오래된 것부터.
   - 숏폼 대기 = 건 폴더에 `20_쇼츠기획.md` 가 있고, 롱폼 `30_결과.md` 가 «상태: 완료»이고, `40_쇼츠결과.md` 가 «상태: 완료»가 아님.
   - 롱폼이 아직이면 그 건은 건너뛴다(기다리지 않는다). 숏폼 대기가 없으면 «할 것 없음»으로 끝.
1-1. (처음 한 번 · 이후 받기만) 숏폼자동화 원본 저장소를 **저장소 밖**에 읽기 전용으로: `git clone https://github.com/hanbizinfo1-boop/shortform-automation.git "D:\숏폼참고\shortform-automation"` — 있으면 `git -C "D:\숏폼참고\shortform-automation" pull`. `D:\숏폼전용` 안에 두지 않는다(`올리기` 가 쓸어 담는다). 고치지 않는다.
2. 정독(발췌 X, 전문): `피드백/절대금지.md`(특히 [10-12 쇼츠] 줄 전부) → `피드백/원하는영상.md` → **그 건의 `20_쇼츠기획.md` 전부** → `20_대본.md` · `20_고정댓글.md` · `20_재현자료.md` → 롱폼 `30_결과.md`(납품 경로 · 정렬 결과 · 바뀐 곳) → `.claude/skills/longform/references/study/sjk-ref-1014.md` 8장 → 이 파일 2~4장 → 원본 참고 `D:\숏폼참고\shortform-automation\.claude\skills\shortform\` `SKILL.md` · `references/s6-longform-shorts.md` · `vertical-spec.md` · `captions.md` · `sfx.md` · `checklist.md` · `feedback-log.md`(사장님 쇼츠 피드백 원문). 부딪히면 **이 저장소(성제관 쇼츠기획·이 파일)가 이긴다** — 원본은 한비즈 광고·강의 쇼츠 기준이라 사람 PIP·잘라 쓰기 규칙이 섞여 있다. 원본 도구(`tools/s6_check.py` · `caption_sync.py` · `align_chars.py` 등)는 `tools_shorts/` 로 복사해 고쳐 쓴다.
3. 만들기(2장) → 검수 두 번(3장) → `납품/<건>_쇼츠/` 탐색기로 열기 → `40_쇼츠결과.md` → `python tools/handoff.py 올리기 "<건> 쇼츠"`.
4. 이 말은 그 범위의 받기·커밋·푸시까지 시킨 것(CLAUDE.md 6번 예외). 밤샘이면 승인 요청 없이 끝까지, 문제는 `40_쇼츠결과.md` «멈춘 곳»에.

## 2. 만드는 법 — 규칙은 «건 폴더의 쇼츠 기획» 이 기준

- **롱폼 렌더를 잘라 쓰지 않는다.** 롱폼 녹음(지시서의 녹음 경로) + 롱폼 강제 정렬 결과 + 롱폼에서 만든 소재(Codex 이미지·재현 화면 — 롱폼 저장소 `납품/`·`소재/`, 경로는 `역할.local.json` 의 `"롱폼경로"`)를 **읽기만** 해서 세로 1080×1920 판에 다시 놓는다. 롱폼 저장소 파일은 고치지 않는다.
- 성제관 공통(10-15): 새로 만드는 화면·제목 글의 호칭은 **«대표님»**. **이미 만든 1편 산출물(제목·썸네일·쇼츠 S1~S6)은 그대로 둔다**(사장님 10-15 «이미 제작한건 냅둬») · 코드로 그린 **말풍선 X → 채운 꼬리표**(1편 쇼츠기획 3장 S7·S8 «말풍선이 하나씩»도 꼬리표로).
- 세로 배치 · 반려 12가지 표 · CTA · 제작 순서 = `20_쇼츠기획.md` 0~4장 그대로(첫 사례: `핸드오프/2026-10-14_성제관01_AI10가지/20_쇼츠기획.md`).
- 자막 시각은 롱폼 강제 정렬 결과를 그대로(다시 받아쓰지 않는다 — 절대금지 09-28). 모양은 롱폼 자막 글꼴 · 중심 y 1440.
- 연출 엔진: `compose` · `html` · `remotion` · Codex 이미지(무료, 한 세션에 몰아서 · codex 끼리 병렬 금지). **AE 없음.** 유료 생성(Kling·힉스필드)은 장면당 한 건 + 사장님 승인.
- 새 도구는 **`tools_shorts/`** 에 만든다(`tools/` 는 롱폼 제작 세션 것 — 쓰고 싶으면 읽어서 가져다 쓰기만, 고칠 게 있으면 `40_쇼츠결과.md` «반영 요청»). 렌더 도구엔 `tools/rule_check.py` · `tools/glyph_check.py` 를 끼운다(CLAUDE.md 10번).
- 같은 컴퓨터에서 롱폼 세션이 렌더 중이면 느려진다 — 무거운 렌더는 한 편씩.

## 3. 검수 (CLAUDE.md 13번 — 편마다 한 번, 전체 한 번)

## 4. `40_쇼츠결과.md` (숏폼이 쓰는 유일한 보고)

`상태: 완료` · 납품 경로(`D:\숏폼전용\납품\<건>_쇼츠\S1_….mp4 · .srt`) · 편마다 길이·첫 줄·CTA 종류 · 검수 결과 · 바꾼 곳(기획과 다르게 한 것과 이유) · 멈춘 곳 · **받은 피드백(사장님 원문 그대로)** · 길라잡이 반영 요청.
→ 기획 세션이 «결과 확인해» 때 이걸 읽고 이 파일·`20_쇼츠기획`·`피드백/` 에 반영한다(규칙은 기획이 고친다 — 숏폼 세션은 이 파일을 고치지 않는다).

## 5. 1편(성제관01) 처리

1편은 숏폼 세션이 생기기 전 롱폼 밤샘 지시에 쇼츠가 들어 있었고 **이미 나왔다**(S1~S6). 사장님 10-15 «이미 제작한건 냅둬» → **다시 만들거나 고치지 않는다.** 0장 표로 검수한 결과만 `40_쇼츠결과.md` 에 적고(«상태: 완료 — 1편은 검수만»), 고칠 것은 «사장님 확인 요청»으로 남긴다. 사장님 피드백이 오면 그때 고친다. **안 나왔으면** 숏폼 세션이 처음부터 만든다. 2편부터는 롱폼 세션이 쇼츠를 만들지 않는다.
- **납품 위치(10-15 정함)**: 쇼츠 납품은 **`D:\숏폼전용\납품\<건>_쇼츠\` 한 곳**. 1편은 롱폼 저장소 `납품/성제관01_쇼츠/` 의 S1~S6 을 같은 이름으로 이쪽에 **복사해 온 뒤** 여기서 검수·고침(롱폼 저장소 쪽은 읽기만 — 고치지 않는다). `40_쇼츠결과.md` 첫 줄에 «쇼츠 납품은 D:\숏폼전용\납품» 을 적어 사장님이 볼 곳을 하나로.
