## 0. 무음편집 절차 — 안전판 (10-02 확정, 다음 강의부터)

**순서**
1. `python tools/cut_plan_only.py <원본> <폴더> 0.06` — VAD 무음 컷, 앞뒤 여유 0.06초. **경계는 이것으로 끝**(사장님 손과 같은 자리: 말 끝 뒤 0.08 · 말 시작 앞 0.10~0.12초, 5장).
2. `python tools/transcribe_words.py` — 단어 시각(쉼 판정의 거부 조건과 마커에 쓴다).
3. `pause_compress.py` 의 `compress_safe2` — **말 안쪽 쉼만** 사장님 기준으로 줄인다(아래 안전장치).
4. `cut_to_fcpxml_dual.py` — XML. **XML 에는 비율만 넣는다**(`--v2-scale`: 4K 카메라 50 · 1080p 카메라 100 = 전체화면). **위치(center)는 넣지 않는다** — 09-23 프리미어에서 화면 밖으로 나감, 10-12 파트너센터에서 또 넣었다가 되돌림. 30% 왼쪽 아래 배치·원형 마스크는 사장님이 기존 PIP 클립 속성(모션+불투명도)을 붙여 넣어 만든다(6장).
5. 자르지 않고 **마커만** 찍는 것: 단어 없는 짧은 조각(숨·입소리·추임새) · 내용 컷 후보(다시 말함·더듬기·편집자에게 하는 말·화면 읽는 말·홍보·끝인사, 5장 표) · 녹화 화면 계정·고객 정보(흐림 후보).
6. 첫 적용 강의는 사장님 편집 뒤 `cut_diff_study.py` + `--검증`으로 다시 재서 이 문서 숫자를 고친다.

**사장님이 걱정하신 세 가지 → 안전장치**

| 위험 | 안전장치 | 근거 |
|---|---|---|
| **말하는 도중에 자름** | 쉼은 **소리 크기로만** 찾는다(주변 바닥 +8dB 아래가 0.25초 이상). 받아쓰기 **단어 끝 시각은 믿지 않는다**(뒤 무음까지 늘어나 있다). 쉼 안에서 받아쓰기 **단어가 시작하면 거부**(작게 말한 말). 실제 자를 자리에 **바닥 +6dB 넘는 프레임이 하나라도 있으면 거부** | 1차 시험(이 장치 없음)은 단어·말소리를 46곳 깎았다 → 안전판 0곳 |
| **말 끝 잔음이 잘림** | 쉼의 시작 = 소리가 바닥 +8dB 아래로 떨어진 지점(잔음 끝). 거기서 **최소 0.06초**(목표는 남길 쉼의 45%)를 남기고 자른다. 다음 말 앞도 최소 0.06초 | 사장님 경계 여유 하위 25% = 0.04~0.05초 |
| **말이 텀 없이 붙음** | 쉼을 지우지 않고 **줄인다** — 남길 쉼 0.12(쉼 0.35초 미만) · 0.15(0.5 미만) · 0.18초(0.5 이상). **0.25초 미만 쉼은 손대지 않는다** | 사장님 남긴 쉼 0.10~0.17초, 0.18~0.25초 쉼은 58%만 줄이심 |
| 판단이 애매한 조각 | 자르지 않고 마커 | 단어 없는 조각은 사장님도 42%만 지우심 |

**검증(빡이사DB 본편 전체, 사장님 완료본 대비)**

| 지표 | 1차(장치 없음) | **안전판** |
|---|---|---|
| 자른 자리에 말소리(바닥 +10dB) 프레임·단어 시작 | 46곳 | **0곳** |
| 줄인 쉼 | 194곳 · 39초 | 120곳 · 23초 (거부: 단어 시작 16 · 소리 섞임 58) |
| 내가 줄인 쉼 중 사장님도 줄인 비율 | — | **73%** |
| 사장님이 줄인 쉼 중 내가 잡은 비율 | — | **64%** |
| 남긴 쉼 | — | 중앙 0.13초(사장님 0.10~0.17) |

- 못 잡은 36%는 «소리 섞임»으로 거부한 쉼(숨·입소리가 섞인 쉼)이 대부분이다 — **안전 쪽으로 남긴 것**이라 사장님이 손으로 줄이시면 된다.
- 나만 줄인 26곳(사장님은 그대로 두신 쉼)은 남긴 쉼이 0.13초라 말이 붙지는 않는다. 사장님이 강조하려고 둔 쉼일 수 있다 → 첫 적용 때 마커로 같이 표시해 드리고 반응을 본다.
- 안전판으로 줄어드는 시간은 본편 기준 약 23초다. 사장님 추가 작업의 대부분(85%, 482초)은 내용 컷이므로, 무음 쪽은 이 정도가 안전한 상한이다.

**결론**
- 걱정하신 «말 끝 잔음»은 지금 여유(0.06초 + VAD)로 사장님 손과 같은 자리에서 끊기고 있다. 경계는 고칠 게 없다.
- 사장님 손이 가는 무음 작업은 **말 «안쪽»의 0.25초 넘는 쉼**이다. VAD가 말 사이 쉼을 «말 안»으로 묶어서 남기기 때문이다.
- 시간 대부분(85%)은 내용 컷이다. 이건 사장님 판단이 맞고, 내가 할 수 있는 건 «후보 마커»까지다(반복 말 찾기, `disfluency_scan` 계열).

## 3. 쉼 줄이기 1차 시험 — 폐기(10-02, 0장 안전판으로 대체)

규칙: 살린 구간 안에서 바닥 +8dB 아래가 0.25초 넘으면 남길 쉼 0.12(0.35 미만) / 0.15(0.5 미만) / 0.18초로 줄임(말 끝 쪽 45 · 다음 말 쪽 55%).

| 검증(원본 0~2466초) | 값 | 판정 |
|---|---|---|
| 사장님 무음 컷 54초 중 같이 지운 것 | 13.3초(25%) | 낮다 |
| 새 규칙이 지운 25초 중 사장님은 살린 것 | 7.1초 | 과하게 자름 |
| 단어를 30% 넘게 깎은 곳 | 44곳(«이런», «특별», «DB», «3만» …) | **말 도중 자름 — 사장님이 걱정하신 그것** |

→ 소리 크기만으로 찾은 «쉼»에 작게 말한 음절·끝 자음이 섞인다. 다음에 고칠 것:
1. 쉼 판정에 **단어 시각을 금지 구역**으로 같이 쓴다(단어 안쪽은 아무리 조용해도 안 자름). 받아쓰기 단어 끝이 무음까지 늘어나는 건 소리로 앞당겨 맞춘다.
2. 바닥 기준을 구간 전체가 아니라 쉼 앞뒤 0.5초로 좁힌다(작게 말하는 사람·방 울림 차이).
3. 다시 `--검증`을 돌려 **같이 지운 비율 70%↑ · 과하게 자름 1초↓ · 단어 깎음 0**이 나와야 기본값으로 올린다.
4. 단어 없는 조각은 자르지 말고 프리미어 **마커**(«확인»)만 찍는다.

## 4. (10-02 오후 메모 — 0장으로 대체) 다음 강의에 바로 쓰는 것

## 7. 싱크 · 녹화본 함정 (본편 무음편집 10-01 기록에서 — 롱폼에 그대로 쓰인다)

- 사장님 지시(10-01): «싱크1시간 + 디비광고세팅법 녹화본 싱크 맞춰서 싱크1시간 보이스만 남기고 무음편집, 길라잡이 참고».
- 방식: V1 녹화(1080p) · V2 촬영본 4K 50% · A1 촬영본 소리만 · 시퀀스 1920×1080 59.94 · 앞뒤 여유 **0.06초**(`cut_to_fcpxml_dual.py`).
- 무음 컷 예: 64:42.9 → **48:31.1**, 컷 876개 (`cut_plan_only.py`).
- **싱크 함정**: 녹화본은 가변 프레임(평균 29.98)이고 녹화 프로그램의 **소리 시계가 느리다**(소리 3870.8초 < 화면 3875.4초). 소리끼리 맞추면 어긋남이 1.28 → 6.89초로 커진다. 그런데 화면은 소리 기준으로 맞추면 틀린다 — 확인: 촬영본 3516.8초 «자 나왔죠?» ↔ 녹화 화면 3514초에 ChatGPT 이미지로 바뀜. 소리 기준 위치(3510)는 아직 이전 화면, 화면 시계 기준 위치(3514.3)가 맞다.
  → **화면 기준 어긋남 곡선**([촬영본 초, 촬영본−녹화화면 초], 1.24 → 2.53초)을 클립마다 적용. 만든 순서: `sync_curve.py`(소리 포락선 상관, 120초 간격) → 녹화 소리 시각 × (화면 길이/소리 길이)로 화면 시각 환산. `cut_to_fcpxml_dual.py` 가 offset 자리에 곡선 json 을 받는다.
- 녹화본은 Premiere 에서 가변 프레임이 밀리지 않게 **30fps 고정본**(소리 없음, NVENC)으로 바꿔 V1 에 쓴다.
- 싱크 재측정(강의 13강 09-30): 녹화 = 촬영본 − 1.785초, XML 위치에서 두 소리 상관 5곳 모두 4~6ms(1프레임 16.7ms 미만). 두 층 XML(30fps 녹화 + 59.94 촬영본, 시퀀스 59.94) 프리미어 임포트도 확인됨. `rec_av_check.py` 는 녹화 파일 안의 «소리 vs 화면» 어긋남을 본다.
- 컷 여유 이력: 0.2 → 0.12(09-23 사장님 «0.2초 너무 길다») → **0.06**(09-30 «여전히 너무 길어», 다음 강부터. `cut_plan_only.py` 기본값).
- 녹화본에 업체명·고객명·계정이 보이면 **모자이크 자동화(`mosaic_scan.py`·`mosaic_render.py`)는 중단했다**(10-06 사장님 «됐어 그냥 하지마 내가 알아서 블러처리할게» — OCR 25~45분 + 렌더 1시간+, 검수 두 번). 다음에 비슷한 요청이 오면 전 구간 자동보다 **가릴 구간 목록(시각·위치)부터 먼저 드리는** 쪽을 제안한다. 목록은 업체·고객명이 들어 있으니 기록 파일에 남기지 않는다.
