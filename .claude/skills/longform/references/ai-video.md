# AI 이미지·영상 만들 때 주의사항 — 반드시 먼저 읽는다

> 원본: `D:\영상제작\길라잡이\AI영상-주의사항.md` + 메모리 «사람 장면은 실사 사진풍» · «AI 영상 속도 바꾸지 않기» · «유료 생성은 장면당 한 건». 분양 단지 전용 문장(동 모양·외벽·평면도 고정)은 뺐다.
> Codex 이미지나 힉스필드·Kling 영상을 만들기 **전에** 읽는다. **유료 영상화 버튼을 누르기 직전**에는 맨 아래 «영상화 직전 점검»을 한 줄씩 확인한다. 롱폼에서는 실사 장면(가게·공장·상담 장면 등 «그림으로 보여 줘야» 할 것)이 필요할 때만 쓴다 — 대부분의 자료는 애펙·Codex 이미지·실화면으로 끝난다(`motion-graphics.md`).

## 0. 가장 중요한 한 줄

> **시작·끝(참고) 이미지의 질감이 영상에 그대로 옮겨 간다.**
> 이미지가 CG면 영상도 CG(반실사), 이미지가 사진이면 영상도 실사로 나온다. 모델 탓이 아니다.

## 1. 실패 기록 — 정원 장면 반실사 (2026-10-01)

| 단계 | 한 것 | 결과 |
|---|---|---|
| 참고 자료 | 구조를 맞추려고 **CG 조감도·투시도 렌더**를 Codex에 참고로 줌 | Codex가 구조뿐 아니라 **CG 화풍까지** 따라 그림. 쨍한 채도, 장난감 같은 꽃밭, 멀리 작게 박힌 사람 |
| 영상화 | 그 이미지를 시작 이미지로 Gemini image-to-video 3초 | 첫 프레임이 시작 이미지와 같은 그림. **반실사**, 사람이 미니어처처럼 움직임 |
| 사장님 지적 | «실사보단 반실사, 실제 인물들이 걸어다니는 느낌이 아님» | |
| 원인 파악 ① | 같은 Gemini로 만든 다른 구간에서 **사진풍 이미지**로 시작한 장면은 실제 드론 영상처럼 나옴 | 이미지 쪽이 의심됨 |
| 원인 파악 ② (시험) | **프롬프트는 한 글자도 안 바꾸고 시작 이미지만 사진풍으로** 다시 만들어 Gemini 3초(9크레딧) | 걸음, 옷 주름, 햇빛, 잔디 모두 실사. **원인 확정 = 참고 이미지** |

교훈:
- **원인을 모르면 바꾸는 것을 하나만 두고 시험한다.** 모델과 이미지를 같이 바꾸면 무엇이 원인인지 끝내 모른다(사장님 «제미나이가 문제인지도 확실하지 않잖아»).
- 모델을 바꾸기 전에 이미지부터 의심한다. **사람이 나오는 AI 장면의 이미지는 항상 «사진기로 찍은 사진» 톤.**

## 2. 참고 자료 다루는 법

| 자료 | 무엇을 가져오나 | 무엇을 가져오지 않나 |
|---|---|---|
| CG 투시도·조감도·배치도 | **구조만**: 배치·모양·색 | 질감, 채도, 꽃, 사람 표현. 프롬프트에 «질감은 따라 하지 말 것»을 꼭 적는다 |
| 실제 영상 프레임 | 마감재, 가구 톤, 실제 조명 | 인쇄된 창밖 사진 |
| 실제 사진(드론·현장) | 질감, 빛, 색 | 다른 장소의 모양 |
| 레퍼런스 영상 | 팔레트·비율·구간·동작 중 **짚은 요소만** | 통째 모사·타사 이미지를 생성 입력으로 넣지 않는다 |

## 3. Codex 이미지 프롬프트에 꼭 넣는 문장

```
CG·렌더링·광고 투시도·일러스트 느낌 금지. 실제로 사진기(풀프레임, 24~35mm, 눈높이 1.6m 또는 DJI 드론)로 찍은
평범한 사진. 자연광, 채도 낮고 자연스러운 색, 실제 소재 질감(고르지 않은 잔디, 바닥 얼룩·이음매, 옷 주름),
약간의 공기감. 과한 꽃·과한 선명도 금지.
사람은 실제 한국인, 화면 중간 거리에서 크게(키가 화면 높이의 1/4~1/3), 자연스러운 자세, 일부는 살짝 움직임 흐림.
글자·간판·로고·숫자 금지.
```

- 참고 이미지가 CG면 «구조는 이 그림과 같게, 질감은 따라 하지 말 것»을 명시한다.
- **인물 실사가 AI 같지 않게(10-15 사장님 «사람 실사를 그릴때 ai티가 많이 나지않았음 좋겠어 진짜 사람처럼 … 배경도 지금만든건너무 ai같아 질감이나 배경이나»)** — 통한 문장: «REAL, UNEDITED SNAPSHOT — 일반 스마트폰(26mm)으로 친구가 찍은 사진, 구도 살짝 어긋남, 그늘에 노이즈, 화이트밸런스 살짝 틀림» · «조명 = 가게 천장 형광등(평평하고 약간 초록빛) — 영화 조명·주황/청록 보정·림라이트·빛망울 금지» · «배경 = 실제 동네 가게의 낡고 어수선한 물건(마감 후 테이블 위 뒤집힌 의자, 스테인리스 컵, 휴지, 김치 통, 선풍기, 낡은 달력, 닳은 바닥) — 글자는 초점 밖» · «인물 = 모델 아닌 평범한 50대 한국인: 모공·주름·잡티·흰 수염·기름진 이마·부스스한 머리·눈 밑 처짐, 바랜 옷과 얼룩 앞치마, 연출 안 한 표정» · 같은 사람 여러 장은 1번을 참고로. 처음 판(주황 영화 조명·깨끗한 가게·뒷모습)은 «너무 AI 같다»로 반려.
- 여러 장면이 같은 장소·같은 인물이면 외형을 **같은 문장으로 고정**한다. 같은 인물 여러 동작은 앞 그림을 `view_image` 로 물려서 그린다.
- 저장 경로를 프롬프트에 적고, Codex는 저장 폴더에서 실행한다. 작업 루트 밖에는 저장하지 못한다 — 샌드박스 때문에 `소재/` 복사를 못 하면 `_tmp` 에 떨어진다. 경로를 확인해 옮긴다.
- 호출: `powershell -NoProfile -ExecutionPolicy Bypass -File "C:/Users/user/.claude/scripts/codex-run.ps1" -PromptFile "<경로>" -Sandbox workspace-write -Effort medium` (이미지 timeout 최소 600000ms, codex 끼리 병렬 금지, 한 세션에 몰아서 — 1장 약 21초, 첫 호출은 기동 포함 약 60초, portrait 1024×1536 / landscape 1536×1024).
- **글자는 AI 에 맡기지 않는다.** 한글·지명·고유 표기는 바탕만 생성하고 글자는 PIL+Pretendard 로(영상 모델은 «비타민B»를 «에터민B»로 그린다). 레퍼런스 없이 상상한 이미지는 «경험상 다 별로였다».

## 4. 모델 고르기

| 모델 | 블렌더 프리비즈(참조 영상) | 미성년 | 비용 | 쓰는 곳 |
|---|---|---|---|---|
| Gemini Omni Flash 1.1 | **받음** (reference-to-video) | **거절** | 3초 9 · 4초 12 · 5초 15 | 기본. 카메라 길이 중요한 장면. 사진풍 이미지면 사람도 실사 |
| Seedance 2.0 | 받음 (start_image + video_references) | 가능 | 4초 18 · 5초 22.5 | 아이가 나오는 장면 |
| Kling 3.0 | **못 받음** | 가능 | 3초 6 | 프리비즈가 필요 없는 짧은 장면 |

> **10-15 Kling MCP 차단**(`.claude/settings.json` deny `mcp__claude_ai_Kling` — 사장님 지시, 다른 세션 전달). Kling 전용 MCP 는 이 세션들에서 못 부른다. 위 표의 Kling 3.0 이 **힉스필드 안 모델**로 불리는 경우는 차단 대상이 아님(힉스필드는 사장님 «사용해야하는 애들도있으니까» 열어 둠) — 쓰기 전 `models_explore` 로 힉스필드에 있는지 확인, 없으면 Gemini Omni Flash 로.

- 이어지는 두 편은 같은 모델로 만든다(질감 통일).
- **유료 생성은 장면당 한 건**(후보 비교는 무료 Codex 이미지 단계에서 끝낸다). `count` 2 이상·같은 프롬프트 변형 금지. 발주 전 `get_cost`, 발주 뒤 `transactions` 로 실제 차감을 대조. ~~Kling 은 세션에서 `who_am_i` 를 먼저.~~(10-15 Kling MCP 차단) 9:16 크롭 같은 후처리는 로컬(ffmpeg).
- **Seedance 는 비싸다 — 웬만하면 Gemini**(사장님 «시댄스 너무 비싸»). 아이가 꼭 필요한 장면이 아니면 성인만 넣어 Gemini.
- **AI 영상을 구간별로 빠르게·느리게 바꾸지 않는다.** 2배속↔0.8배속 같은 속도 변화는 «중간중간 멈춤»처럼 보인다(사장님 «중간중간 멈춤 효과 뭐야?»). 대사 구간 길이에 맞춰 3·4·5초로 생성하고 1배속(±5% 안)으로 쓴다. 대사 타이밍은 프롬프트·프리비즈의 초 단위 동작으로 맞춘다.
- 사람 장면 영상화: 프리비즈 없이 이미지만 = Kling 3.0. 블렌더 프리비즈가 필요하면 Kling 은 참조 영상을 못 받으므로(사장님 «클링으로 하면 블렌더가 안 되잖아») Seedance 2.0.

## 5. 원테이크 (사장님 «뚝뚝 끊기잖아, 원테이크로»)

- Gemini reference-to-video 에 **시작·끝 이미지를 둘 다** 넣으면 중간에 장면을 바꿔 붙이는(컷) 경우가 있다.
- 한 컷이어야 하는 장면은 **끝 이미지를 빼고** 시작 이미지 1장 + 블렌더 프리비즈 + 프롬프트 «single continuous take, no cuts, no scene changes»로.
- 받은 뒤 프레임을 0.33초 간격으로 늘어놓고 **화면이 뚝 바뀌는 곳이 없는지** 반드시 본다.

## 6. 영상화 직전 점검 — 한 줄씩

```
[ ] 시작·끝 이미지를 직접 열어 봤다 — CG 냄새(쨍한 채도, 장난감 같은 꽃·나무, 완벽히 고른 잔디, 작게 박힌 사람)가 없다
[ ] 사람이 나오면 화면 높이 1/4~1/3 크기로 크게, 실제 한국인, 자연스러운 옷
[ ] 미성년이 있으면 Gemini 말고 Seedance
[ ] 같은 장소·같은 인물이면 외형 문장이 다른 장면과 같다
[ ] 이미지에 글자·간판·로고·숫자 없음 (필요한 글자는 렌더러가 올린다)
[ ] 프리비즈가 필요하면 Kling 아님
[ ] 이어지는 편과 모델이 같다
[ ] 한 컷 장면이면 끝 이미지 빼고, 받은 뒤 컷 바뀜 없는지 프레임으로 확인
[ ] 생성 길이 ≈ 대사 구간 길이 — 나중에 구간별 속도 바꾸기 없음
[ ] 아이가 꼭 필요한가? 아니면 성인만 → Gemini(싸다)
[ ] 앞 편 끝 프레임에서 이어야 하면 그 프레임을 시작 이미지로 썼다
[ ] 장면당 한 건 · 발주 전 get_cost · 비용(크레딧)과 누계를 기록(기록/작업기록.md)에 적었다
```

## 7. 이미지 출처 · 정보 취급 (롱폼 공통)

- 이미지는 **레퍼런스를 보고** 만든다. 받은 로고·이미지는 파일·주소·받은 날을 `소재/이미지-출처.md` 에 한 줄씩(403·봇 차단은 우회하지 않는다).
- **업체명·대표번호·계정 정보가 보이는 실자료는 쓰지 않는다**(10-01 «업체명 나오면 문제 생길 수 있어서 그냥 연출로»). 그 자리는 Codex 연출 이미지, 또는 같은 결로 다시 그린 화면(업체 ○○ · 010-0000-0000). 이 규칙은 «이미지는 실자료만»(분양 광고 한정)보다 우선한다.
- 위키미디어 썸네일은 표준 크기(250·500px 등)만 받아 준다 — API `prop=imageinfo&iiurlwidth=500` 로 주소를 얻는다.
