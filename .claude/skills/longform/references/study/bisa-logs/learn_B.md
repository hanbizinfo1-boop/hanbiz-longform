## 3. 기술 함정과 해결 (수치·명령 포함)

### 3-A. 오디오 분석 스택 (예능 조사)
- **설치:** CUDA torch 2.6 + demucs(htdemucs) + PANNs(`panns_inference`, Cnn14, 체크포인트 `~/panns_data`). Cnn14 분류 + `Cnn14_DecisionLevelMax` SED 를 20fps 로.
- **yt-dlp 구간 받기 함정:** `--download-sections` + `--force-keyframes-at-cuts` 가 CPU 재인코딩으로 첫 편에서 0바이트 정지. 해결: 480p 전체를 받은 뒤 ffmpeg `-c copy` 로 자르기(`yeneung_fetch.py`, 인자: 초, 최대높이). 쇼츠는 세로 영상이라 자막을 읽을 수 있게 해상도를 조금 높여 받음. 403/429 는 **우회하지 않고 건너뜀**(슈카월드 1편 403, 쇼츠 4편 429).
- **info.json BOM:** 파싱 오류 → 일괄 제거.
- **라벨만으로 검출 → 재현율 8%.** 해결: 온셋 검출기 `yeneung_onset.py` — 배경 중앙값(2초) 대비 +9dB 이상이고 음색 변화(cosine ≥ 0.05), 또는 0.4초에 +12dB 이상 상승. 악기·드럼 상위 라벨은 제외. **자체 시험 믹스(`yeneung_selftest_mix.py`, 정답을 아는 합성)** 로 효과음 25개 중 12~13개 검출(큰 소리 10개 중 7개), 헛검출 5개 → **자동 개수는 최소치로만 읽음**.
- **음악 오검출:** 배경음악 드럼이 효과음으로 잡힘 → `DRUM_BEAT` 필터 + 마디 반복 필터 시험.
- **화면 검출 한계:** 화면 아래 큰 예능 자막을 «대사 자막» 으로 분류해 놓침 → «자막에 효과음 붙는 비율»은 기계가 아니라 **정독에서 사람이 판단한 계기** 기준으로 집계.
- **정독 방식 함정:** 서브에이전트가 띠 그림(사건당 3프레임 + 대사)을 수십 장 열다 `media removed: request limit` 으로 앞 그림이 맥락에서 지워짐 → 지침 개정: **그림 한 장 보고 바로 그 장의 판정을 파일에 저장**.
- **직접 재검증:** 클로드가 «높음» 으로 적힌 장면 하나를 직접 띠 그림으로 열어 검증(놀면뭐하니 «역사→역사·재미→역사·재미·먹거리 풀코스», 4.3kHz 음정 소리, 0.5~0.96초, 목소리보다 3~5dB 작음) — **서브에이전트 요약을 그대로 믿지 않고 한 건 이상 직접 확인**.
- **채널/영상 선정:** `yeneung_pick.py` — 3~40분 영상 중 «채널 중앙 조회수 대비 배수» 상위 3편. 문명특급은 뮤직비디오·공연이 상위에 잡혀 제외 후 재선정. 분석은 편당 앞 8분.
- **채널별 요점(기존 실측 문서와 같음):** 밀도는 음악 사용과 같이 감(워크맨 분당 9~16, 놀면뭐하니 6~8, 네고왕 5~8 / 노빠꾸 1~3 / 핑계고·침착맨·슈카월드 거의 없음). 슈카월드는 숫자·자료 화면에도 효과음 없이 펜 밑줄·동그라미가 강조 담당. 네고왕은 효과음 73%가 자막 등장 순간.
- **웹조사:** 서브에이전트 «한국 예능 효과음 문법 웹 조사» 결과를 대화가 요약되면 사라지므로 **받자마자 파일로** 저장(`예능효과음-웹조사.md`). 효과음 24종 쓰임, 타이밍 실험(Kim et al. 2016: 웃긴 장면 0~0.5초 뒤 / 사고형 0.5~1초 뒤).

## 6. 자동화로 옮길 때의 빈칸

### 6-A. 사람 판단이 꼭 필요했던 지점
1. **시안 선택**(02 A/B/C, 03 A/B). 무인 모드에서는 시안 기본값 규칙이 필요.
2. **레이아웃 취향**: «사람 왼쪽 + 오른쪽 판 반반, 겹침 없음» 은 반려로 확정. 01 에서 통과한 레이아웃을 이후 장면의 기본형으로 삼을 수 있음(02·03 은 따라서 통과).
3. **효과음 자리별 선택**: 등급표는 결만 보고 뜻 모름 → 자리마다 파일 이름으로 고정(sfx-workflow.md 가 반영). 통과/반려는 사장님이 실제 편집에서 쓰고 지운 결과로만 알 수 있다(청음 금지).

5. **업체명·계정이 나오는 실화면** 사용 여부는 눈으로 확인(주소창·탭·북마크). 자동화는 흐림 후보 마커까지.
6. **방향 전환 가능성**: 사장님이 «이미지가 마음에 안 들어 노트에…» 처럼 연출 방향을 뒤집을 수 있음 → 밤샘 모드에서는 복수 후보를 만들어 두는 게 안전(추정).

### 6-B. 자동화하면 위험한 지점
1. **자르기** — 필요한 말이 잘리는 것이 최대 걱정. whisper 단어 시각을 믿지 말 것(44곳 깎임). 자동 쉼 줄이기는 안전판 + 손상 0 검증을 통과할 때만 저장. 컷은 마커만.
2. **같은 효과음 반복** — 3초 안에 같은 파일 3번 초과 금지. 카드 8장 같은 연타 자리에는 결이 비슷한 다른 파일 4~5개 필요. 점검기 ERROR 면 렌더 중단.
3. **효과음 크기 환산** — «+3dB» 같은 상대 지시는 기준 없이는 틀리게 환산됨. 목소리 대비 일반 −2 / 휙 −3 / 펜 −8 을 절대 기준으로.
4. **짧은 소리 증폭 클리핑** — 피크 −6dBFS 상한 필수, 렌더 후 `ebur128=peak=true` 로 반드시 측정.
5. **실화면** — 업체명·계정이 섞임. 직접 그린 모형 또는 Codex 연출로 대체.
6. **렌더 형태** — 사람이 움직이면 알파 .mov 불가. 장면 설계 단계에서 사람 포함 mp4 vs 알파 mov 결정.
7. **사장님이 프리미어에서 편집 중** — 자동저장본 사본으로만 읽기. 납품은 같은 이름 덮어쓰기라 잠긴 파일 가능성.
8. **정체불명 파일**(`x.jpg`) — 커밋·삭제 모두 하지 않고 남김.
9. **사용량 한도** — 서브에이전트 대량 정독은 중간에 끊김. 판정 즉시 저장 + 끝난 편 건너뛰는 배치 필수.
10. **저작권** — 効果音ラボ 소재는 재배포 금지(이 PC 에만). 상표 로고 사용 안 함. 접속 차단(403/429)은 우회하지 않음.
